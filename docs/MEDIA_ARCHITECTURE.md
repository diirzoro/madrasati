# Media architecture (developer reference)

The detail/profile pages are media-driven. This document is the developer
contract for how media is owned, resolved and uploaded.

See also `design-prototype-v4/assets/MEDIA.md` for the asset-tree version, and
`docs/TAHER_ARCHITECTURE_AND_DASHBOARD_CONTROL_MAP.md` for the product map.

## Principle

**ONE ENTITY = ONE MEDIA ROOT. DATABASE ID = MEDIA OWNER. NAME = LABEL ONLY.**

Names are never identity: they duplicate, change, misspell and localize. Only the
database id owns media.

## Roots

```
assets/
  institutions/
    private-schools/<id>[-label]/{logo,cover,gallery,facilities,documents}/
    government-schools/<id>[-label]/{logo,cover,gallery,facilities,documents}/
    institutes/<id>[-label]/{logo,cover,gallery,facilities,documents}/
    colleges/<id>[-label]/{logo,cover,gallery,facilities,documents}/
    universities/<id>[-label]/{logo,cover,gallery,facilities,documents}/
  teachers/<male|female>/<id>[-label]/{profile,cover,gallery,documents}/
  users/<id>/{avatar,documents}/
  owners/<id>/{profile,documents}/
  reference/                     # generic fallback ONLY
    institutions/<type>/{cover,logo}.svg
    institutions/shared/<cover-NN.jpg>
    teachers/{male,female}/profile-NN.jpg
```

`<id>[-label]` — the id is mandatory and comes first; the slug is a readable
suffix only. `125` and `125-noor-school` both belong to org id 125.

## Resolver (`design-prototype-v4/media.js`)

- `MadrasatiMedia.orgMedia(org)` → `{ root, logo, cover, gallery, generic, ref }`
- `MadrasatiMedia.teacherMedia(teacher)` → `{ root, avatar, cover, gallery, generic, gender, ref }`
- `MadrasatiMedia.resolvePath({ entityType, entityId, mediaType, orgType|gender, label })` → upload folder
- Helpers: `orgRoot`, `teacherRoot`, `userRoot`, `ownerRoot`, `segment`, `typeFolder`, `hash`

Resolution order: DB media → `media-map.js` → upload root → generic reference
(deterministic by id, flagged `generic:true`).

## Explicit mapping (`design-prototype-v4/media-map.js`)

Auto-generated by `scripts/media-map-build.js` from the database. Maps
`organization.id` / `teacher_profiles.id` to existing project assets (e.g. the
seeded `assets/logos/<slug>.svg`). The filename is not the identity; the id is.

## Provisioning & uploads

- `scripts/media-init.js` creates an entity's root and category folders.
- Uploads pass `entity_type` + `entity_id` + `media_type`; the destination is
  derived from the authenticated entity id, never from a frontend path.

## Guarantees

- No random media, no cross-entity mixing.
- Duplicate names → independent roots (ids differ).
- Renames → ownership unchanged (id stable).
- Generic reference media is never treated as a named entity's real media.
- Scales to 10k+ entities: the tree is id-keyed and deterministic.
